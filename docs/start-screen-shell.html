System Shell: 4 iterations

Follow-up to direction 02 in start-screen-mockups.html. The world is the same; each iteration changes how much screen the shell takes and how it talks.

Kept in every iteration

  • The system's voice: cold, logged, timestamped. It counts Bob's failed escapes and calls the weekly reset a "purge".
  • Bob talks back: one line in magenta that isn't the system's. It's the hint that he's breaking out.
  • BREAK OUT is always first and pre-selected, with the input next to it. TRAINING and CONTROLS sit right under it.
  • The leaderboard becomes subject records: your row highlighted in place, distance to #1 as a bar.
  • The logo has a small red/cyan split, like a glitchy display.

Changed from 02

  • Panel 33% → 30% wide, so Bob and the pane have more room.
  • Log lines get timestamps and type in one by one on load (static if reduced motion is on).
  • Commands are numbered; only the selected one shows its key.
  • "Purge in 4d 23h" instead of "resets in".

Watch out for

  • The log is flavour; it must not push the menu down on short screens. Cut it to 2 lines first.
  • The type-in should only run on the first visit of a session, or it gets old.

Effort

  • Medium. One cached panel (panelCache.js), three hit areas in ui/layout.js, start camera shifted right.

Changed from 02

  • No full-height panel: two compact windows, so more of the city shows.
  • Commands read like terminal commands (./break_out, man controls), with a one-line description.
  • Records live in their own window, so they can be closed or moved later.

Watch out for

  • Desktop "windows" look like a PC game; not great on phones.
  • The firewall has to sit lower to clear the windows.
  • The $ ./ syntax reads as a joke to programmers and as noise to everyone else.

Effort

  • Medium. Two cached panels instead of one; same hit areas as A.
C

Drop-down console

The shell drops down from the top like a game console. Log and title on the left, records on the right, and a command prompt along the bottom edge. Bob's line also appears as a speech bubble over him in the world.

Changed from 02

  • Horizontal instead of vertical: the whole width of the world stays visible, and Bob keeps his usual spot.
  • The menu is a prompt with three chips; the selected chip is what's "typed".
  • Bob's reply leaves the shell and appears over him, so the world and UI talk to each other.

Watch out for

  • The console is a natural thing to animate: it could retract upward as Bob hits the firewall.
  • Top 35% of the sky is covered; tall screens are fine, very wide short ones get tight.

Effort

  • Medium. One cached panel; the speech bubble is a small world-space draw above Bob.

How it maps from A

  • Status line and title → top strip over the world.
  • Log → just the last two lines (the warning and Bob's reply).
  • Menu → one big button and two small ones, all thumb-sized.
  • Records → a single "#2 this week" row; tapping it opens the full board as a sheet.

Watch out for

  • On phones, tapping anywhere already jumps. Only the BREAK OUT button (and the world above the sheet) should start the run, so a tap on TRAINING never launches Bob by accident.
  • Check the mobile control buttons (#mobile-controls) are hidden while the sheet is up.

Effort

  • Medium. A second layout for the same panel in ui/layout.js, picked by aspect ratio.
